\section{Судалгааны арга зүй}
\label{sec:methodology}

Энэ бүлэгт Egüü системийн шаардлагыг тодорхойлж, системийн шинжилгээ, зохиомж, архитектурын шийдлүүдийг дэлгэрэнгүй танилцуулна. Мөн хэрэглэгчийн интерфэйс (UI/UX) модель, өгөгдлийн сангийн зохиомжийг авч үзнэ.

\subsection{Судалгааны арга зүйн дараалал}
\label{subsec:method-sequence}

Энэхүү ТСА нь дараах 3 үе шаттай логик дарааллаар хэрэгжсэн. Үе шат бүр өмнөх шатны үр дүнд тулгуурлан дараагийн шийдлийг тодорхойлсон нь судалгааны дотоод уялдаа, баталгаажуулалтын чанарыг хангах үндэс болсон.

\begin{enumerate}
    \item \textbf{Модель сургалт ба OCR-ийн урьдчилсан бэлтгэл:} Монгол бичгийн үсэг таних OCR модулийн өгөгдлийн бэлтгэл, таних урсгалын (preprocessing \textrightarrow{} inference \textrightarrow{} post-processing) шаардлагыг тодорхойлж, TensorFlow.js-ээр ажиллах моделийн интеграцийн нөхцөлийг урьдчилан тогтоосон.

    \item \textbf{Аппликейшн хөгжүүлэлт ба системийн интеграц:} React Native/Expo дээр хэрэглэгчийн интерфэйс, Firebase backend, flashcard ба SM-2 алгоритмын логик, OCR функцийг нэгтгэн системийн үндсэн функцуудыг хэрэгжүүлсэн.

    \item \textbf{Туршилт, хэрэглэгчийн санал хүсэлт ба үнэлгээ:} Хөгжүүлсэн систем дээр функциональ ба гүйцэтгэлийн шалгалт хийж, хэрэглэгчийн туршилтаар ашиглахад ойлгомжтой байдал, үр нөлөө, сайжруулах шаардлагатай хэсгүүдийг тодорхойлсон.
\end{enumerate}

Дээрх дарааллын дагуу онолын үндэслэл, инженерийн хэрэгжүүлэлт, хэрэглээний үнэлгээг нэг шугамд уялдуулснаар ТСА-ийн зорилго, зорилтын биелэлтийг шат дараатайгаар баталгаажуулсан.

\subsection{Системийн архитектур болон зохиомжийн шийдлүүд}
\label{subsec:design-decisions}

Энэхүү дэд бүлэгт Egüü системийн ерөнхий архитектур, хэрэглэгчийн интерфэйсийн зохиомж болон хөгжүүлэлтэд сонгогдсон технологийн стекийн (technology stack) үндэслэлийг шинжлэх ухаан, инженерчлэлийн үүднээс нарийвчлан тайлбарлах болно.

\subsubsection{Гадаад зохиомж буюу Хэрэглэгчийн интерфэйс (External Design)}

\textbf{Хэрэглэгчтэй харилцах хэсэг (Frontend UI):} Egüü систем нь орчин үеийн мобайл аппликейшны стандартын дагуу ``Tab-based'' буюу цэсэнд суурилсан навигацийн бүтцийг ашигласан бөгөөд Нүүр, Хайлт, Дуртай, Профайл, Камер гэсэн 5 үндсэн дэлгэцээс бүрдэнэ. Сургалтын хэрэглэгдэхүүн болох Flashcard-уудыг танин мэдэхүйн ачааллыг бууруулах зорилгоор эгшиг, гийгүүлэгч, үг зэрэг дэд категориудад системтэйгээр ангилсан болно. Мөн үг хайлтын ухаалаг функц нь хэрэглэгчид шаардлагатай мэдээллээ богино хугацаанд олох, интуитив (хялбар ойлгогдох) туршлагаар хангах зорилготой юм.

\paragraph{Гадаад зохиомжийн үндсэн шийдлүүд нь дараах байдалтай.}

\begin{itemize}
    \item \textbf{Навигаци:} Tab-based навигаци ашигласан нь хэрэглэгч хамгийн түгээмэл хэрэглэгддэг дэлгэцүүд рүү нэг товшилтоор шилжих боломжтой болгодог
    
    \item \textbf{Категоризаци:} Flashcard-уудыг категориор ангилсан нь хэрэглэгч өөрийн сонирхсон хэсгээс эхлэн суралцах боломжтой
    
    \item \textbf{Хайлт:} Фонетик, англи орчуулга, тодорхойлолтоор хайх боломжтой нь хэрэглэгч хурдан олох боломжтой
    
    \item \textbf{Gamification элементүүд:} Streak counter, daily word, progress bar зэрэг нь хэрэглэгчийн мотивацийг нэмэгдүүлдэг
\end{itemize}

\subsubsection{Дотоод зохиомж буюу Системийн архитектур (Internal Design)}

Систем нь client–server архитектур дээр суурилсан. React Native дээр хөгжүүлсэн клиент тал нь хэрэглэгчтэй харилцах интерфэйс болон үндсэн үйлдлүүдийг хариуцаж, Firebase backend-тэй холбогдон authentication, database, storage зэрэг үйлчилгээг ашиглана. Мөн TensorFlow.js дээр суурилсан OCR модуль нь гар бичмэлийг таних ажиллагааг гүйцэтгэж, сервертэй мэдээлэл солилцоно. Харин сургалтын логик болох spaced repetition алгоритм нь клиент талд ажиллаж, хэрэглэгчийн суралцах явцыг удирдана. Өгөгдлийн хадгалалт болон шинэчлэлтийг Firebase гүйцэтгэнэ.
\subsubsection{Өгөгдлийн сангийн архитектурын шийдэл}

Cloud Firestore NoSQL сонгосон байна. Энэ сонголтын үндэслэл: Бодит цагийн синхрончлол, offline persistence, auto-scalability зэрэг давуу талууд. Document-based бүтэц нь flashcard объектуудыг (уламжлалт бичиг, галиг, орчуулга, тодорхойлолт, зураг) үр дүнтэйгээр хадгалахад оновчтой юм.

\subsubsection{Программ хангамжийн технологийн стек (Technology Stack)}

React Native (cross-platform), Firebase (BaaS, real-time), TensorFlow.js (client-side ML, хувийн нууцлал), NativeWind (Tailwind CSS), react-i18next (олон хэл). Энэ стек нь хөгжүүлэлтийн цаг хэмнэж, найдвартай системтүүлж, засварын зардлыг бууруулдаг. Дэлгэрэнгүй төлөвлөгөөнүүд Хавсралт А-д орлуулсан.



\subsection{Системийн шаардлага}
\label{subsec:requirements}

\subsubsection{Функциональ шаардлага}

Egüü системийн функциональ шаардлагуудыг дараах байдлаар ангилж тодорхойлно.

\begin{itemize}
\item \textbf{Хэрэглэгчийн удирдлага:} Email/Password болон Google Sign-In ашиглан нэвтрэх, хэрэглэгчийн профайл мэдээллийг засварлах боломжийг олгоно.

\item \textbf{Flashcard систем:} Монгол үсгүүдийг зураг, фонетик болон англи орчуулгатайгаар харуулж, spaced repetition аргачлалд суурилсан давталтын сургалтыг хэрэгжүүлнэ.

\item \textbf{Категори ба хайлт:} Үсгүүдийг ангиллаар бүлэглэх болон фонетик мэдээллээр хайх боломжийг олгоно.

\item \textbf{Дуртай жагсаалт:} Хэрэглэгч дуртай үсгүүдийг хадгалах, нэмэх болон хасах үйлдлийг гүйцэтгэнэ.

\item \textbf{Streak tracking ба Daily Word:} Өдөр тутмын идэвхийг хянах болон өдөр бүр шинэ үг/үсэг санал болгох системтэй байна.

\item \textbf{OCR систем:} Гар бичмэл Монгол үсгийг таних зориулалттай TensorFlow-д суурилсан модуль ашиглана.

\item \textbf{Олон хэлний дэмжлэг:} Монгол болон Англи хэлний интерфэйсийг дэмжинэ.

\item \textbf{Theme тохиргоо:} Хэрэглэгч light болон dark горимын хооронд солих боломжтой.
\end{itemize}

\subsubsection{Функциональ бус шаардлага}

\begin{itemize}
\item \textbf{Гүйцэтгэл:} Аппликейшн 3 секундээс бага хугацаанд ачаалж, OCR таних процесс 2 секундээс хэтрэхгүй байна.

\item \textbf{Хэрэглэхэд хялбар байдал:} Ойлгомжтой хэрэглэгчийн интерфэйстэй бөгөөд шинэ хэрэглэгч 5 минутын дотор үндсэн үйлдлүүдийг ойлгож ашиглах боломжтой.

\item \textbf{Найдвартай байдал:} Систем 99\% хүртэл тасралтгүй ажиллагаатай, Firebase backup ашиглан өгөгдөл алдагдахаас сэргийлсэн бөгөөд offline горимыг дэмжинэ.

\item \textbf{Аюулгүй байдал:} Нууц үгийг hash хэлбэрээр хадгалах, Firebase Security Rules ашиглах, HTTPS протокол хэрэглэх замаар өгөгдлийн аюулгүй байдлыг хангана.

\item \textbf{Өргөтгөх боломж:} 10,000+ хэрэглэгчийг дэмжих чадвартай бөгөөд flashcard нэмэх, шинэ хэл болон функц өргөтгөхөд хялбар архитектуртай байна.
\end{itemize}

\paragraph{Архитектурын тайлбар:}

Client (React Native) нь Firebase (Cloud Firestore, Authentication, Storage) болон TensorFlow.js OCR-ээр харилцан ажиллана. Apп нь Expo Router навигаци, NativeWind UI, Context API төлөв удирдалгатай бүтээгдсэн.

\subsubsection{Модуляр архитектур}

Аппликейшний бүтэц нь screens (tab навигаци, camera, settings), components (UI элементүүд), services (Firebase, OCR, i18n), contexts (төлөв удирдлага), utils (spaced repetition алгоритм) гэсэн үндсэн хэсгүүдээс бүрдэнэ. Энэ бүтэц нь шинэ функц нэмэх болон засвар хийхэд хялбар, өргөтгөх боломжтой байдлыг хангана.

\subsection{Өгөгдлийн сангийн зохиомж}
\label{subsec:database-design}

\subsubsection{Firestore өгөгдлийн бүтэц}

Firestore нь 5 үндсэн collection-оос бүрдэнэ. Үүнд: Flashcards (үсэг, үг, зураг), Users (хэрэглэгчийн мэдээлэл, streak, статистик), UserProgress (SM-2 алгоритмын дагуу суралцах явц, дараагийн давталтын мэдээлэл), Favorites (дуртай жагсаалт), болон DailyWords (өдөр тутмын үг) орно. Collection-ууд хоорондоо холбоотой бөгөөд Users нь UserProgress-тэй, мөн Flashcards нь UserProgress-тэй уялдан ажиллана. Бүтцийн дэлгэрэнгүйг Хавсралт A-д харуулсан.

\subsection{Хэрэглэгчийн интерфэйс (UI/UX) модель}
\label{subsec:ui-ux-design}

UI/UX дизайнын зарчмууд: (1) Энгийн, ойлгомжтой интерфэйс; (2) Монгол соёлын элементүүд; (3) Орчин үеийн дизайн; (4) Accessibility дэмжлэг; (5) Тууштай дизайн. Өнгөний палитр: Primary Blue и Success Green. 4 үндсэн дэлгэц: Нүүр (Daily Word, Streak), Flashcard суралцах, Хайлт, OCR камер.

\subsection{Spaced Repetition алгоритм}
\label{subsec:spaced-repetition-implementation}

SuperMemo 2 (SM-2) алгоритмыг хэрэгжүүлсэн. Алгоритм нь: (1) Хэрэглэгч үнэлгээ өгнө (0-5); (2) Үнэлгээнээс үндэслэн Easiness Factor, interval (хоног), repetition тооцоолно.

\subsection{Бүлгийн дүгнэлт}

Энэхүү бүлэгт ТСА-ийн хүрээнд Egüü системийн шаардлага, архитектур, өгөгдлийн модель, UI/UX шийдэл болон SM-2 алгоритмын зохиомжийг тодорхойллоо. Дараагийн бүлэгт эдгээр зохиомжийг бодит кодчилол, интеграц, туршилтын түвшинд хэрхэн хэрэгжүүлснийг тайлбарлана.
